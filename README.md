# 时间统计 TimeStats

一个模仿 Steam「游玩时长」的 Windows 小工具：把常用的游戏 / 软件加进来，从它里面启动，
它就自动记录你用了多久、每天几点开始几点结束。绿色免安装，不联网、不上传、不需要账号。

**[⬇ 下载最新版](https://github.com/tyis19/time-stats/releases/latest)** · Windows 10 / 11 · 约 290MB（自带运行环境，解压即用）

---

## 它是什么

Steam 会替你记住每个游戏玩了多少小时。但不在 Steam 上的游戏、以及各种软件，就没人管了。

这个工具补上这块：卡片墙上摆着你的软件，点「开始」就计时，关掉自动停表；
也可以开「自动监视」，你从桌面、开始菜单、Steam 哪里启动的都照样统计。

数据全部存在本地的一个文件夹里，拷走就能换电脑，删掉就等于没发生过。

## 功能

- **卡片墙**：加一个 exe，图标和名字自动读出来，不用手填
- **两种计时方式**：手动点「开始」；或开「自动监视」，从任何地方启动都统计
- **自动停表**：游戏关掉后 3～9 秒自动结束并写入记录
- **5 秒确认**：自动监视时，进程要先活过 5 秒才算一次使用，一闪而过的启动器不会留下垃圾记录
- **启动器交接**：先起启动器、再拉起游戏本体的游戏，会自动把计时交接给真正的进程（主进程退出后 15 秒内，同一个安装目录里出现新进程就接上）
- **跨天拆分**：22:00 玩到次日 02:00，自动算成前一天 2 小时 + 后一天 2 小时
- **睡眠扣除**：电脑睡眠的时间单独标出，默认不计入有效时长
- **记错能改**：记录归错了软件，可以原地改到正确的卡片上，时长和起止时间都不动
- **诊断日志**：某个软件总是记不上时，打开它就能看到每一步的判断过程
- **统计与图表**：按天 / 周 / 月度看总时长、分布、每天几点到几点
- **导出表格**：一键导出 CSV，用 Excel 打开
- **托盘常驻**：点叉号不退出，缩到托盘继续计时
- **开机自启**：在启动文件夹放一个快捷方式实现，不改注册表，杀软更少误报
- **自动备份**：每天首次打开时备份一次数据，保留最近 7 天

## 下载与安装

1. 打开 [Releases](https://github.com/tyis19/time-stats/releases/latest)，下载 `TimeStats-v1.1.0-win-x64.zip`
2. 解压到任意目录（**不要**直接在压缩包里双击运行）
3. 双击 `TimeStats.exe`

第一次打开 Windows 可能问一句「是否允许」，点允许即可。
程序没有代码签名，个别杀毒软件可能误报，把解压后的文件夹加入信任名单即可。

## 怎么用

- **加软件**：右上角「＋ 新建」→ 选中要统计的 exe → 点「打开」
- **开始计时**：卡片上点「开始」
- **自动监视**：设置 → 打开「自动监视」；之后从任何地方启动库里的程序都会被记录
- **彻底退出**：托盘图标右键 →「退出」，或设置页点「退出程序」

游戏要选你平时双击的那个启动程序，不一定叫「游戏名.exe」，也可能是「开始游戏.exe」。

## 数据存在哪里

就在 `TimeStats.exe` 旁边的 `data` 文件夹（首次运行自动创建）：

```
data/
├─ apps.json          软件清单（名字、路径、图标）
├─ sessions.ndjson    使用流水账，一行一次使用，只追加
├─ settings.json      你的设置
├─ backup/            每天自动备份，保留 7 天
├─ icons/             图标缓存
└─ debug.log          诊断日志（默认不生成，在设置里打开后才写）
```

想换电脑：把整个程序文件夹拷过去，历史记录全在。
想清空：删掉 `data` 文件夹即可。

## 从源码运行

需要 Node.js。程序基于 Electron 43.3.0。

```bash
# 1. 准备运行环境（从本机 Electron 缓存解压到 vendor/）
node scripts/extract-electron.js

# 2. 开发模式启动（改完源码直接看效果）
node scripts/dev.js
```

> `extract-electron.js` 读取的是 Electron 官方缓存目录里的 `electron-v43.3.0-win32-x64.zip`。
> 本机没有缓存的话，先用 npm 装一次 Electron 43.3.0 让它下载缓存，或自行把该 zip 放到对应缓存路径。

## 打包成绿色版

```bash
node scripts/build.js
```

产物在 `dist\时间统计\`。打包前先把正在运行的程序退出，否则改不了文件名。

> 打包只会替换运行环境文件，**不会动 `dist\时间统计\data`**（你的历史记录）。这一点写在脚本里了，别再改回「整个目录删掉重建」——那会连记录一起清空。

## 自检脚本

```bash
node scripts/probe.js                # 检查进程扫描是否正常
node scripts/test-stats.js           # 检查跨天拆分等统计算法
node scripts/test-tracker-logic.js   # 检查去抖、交接、防 PID 复用、中断扣除（不用启动真实程序）
```

`scripts/` 下另有几个真机 GUI 测试（tracker、handover、shortcut），需要 `vendor/` 里的运行环境。

## 目录结构

```
src/
├─ main/                  主进程
│  ├─ main.js             入口：单实例锁、托盘、睡眠、启动恢复
│  ├─ ipc.js              界面能调用的所有功能（通道清单）
│  └─ services/
│     ├─ tracker.js       ★ 计时状态机（判活、去抖、启动器交接、中断扣除）
│     ├─ process-scan.js  ★ 进程扫描（CSV 解析、GBK 中文名、进程号带名字）
│     ├─ process-detail.js 按需查进程真实路径（撞名区分、同目录交接用）
│     ├─ logger.js        诊断日志（默认关闭，2MB 轮转留 3 份）
│     ├─ launcher.js      启动程序 / 强制关闭
│     ├─ sessions.js      流水账（一行一次使用）
│     ├─ stats.js         统计口径（跨天拆分、休眠扣除）
│     ├─ apps.js          软件库、读 exe 名字和图标
│     └─ autolaunch.js    开机自启（启动文件夹快捷方式）
├─ renderer/              界面（原生 HTML/CSS/JS，没有框架）
└─ preload/               IPC 桥接

scripts/                  打包、调试、测试、生成图标
vendor/                   Electron 运行环境（348MB，可用脚本重新解压，不入库）
dist/                     打包产物（不入库）
```

### 几个关键约定（改代码时别破坏）

- 数据只写在 `data/` 里，程序其他文件不改
- `sessions.ndjson` 只追加、不改写（删单条、改归属时才整体重写）
- 结束时间取「最后一次看到进程 + 半个轮询周期」，避免系统性少算
- 跨天会话在统计时才拆分，存储里保留真实的开始 / 结束
- 自动监视默认关闭；用户打开后，启动程序时必须立刻 `ensureTimer()`
- **判活必须同时核对进程号和进程名**。只核对号的话，进程号被系统回收再分配时会以为程序还开着，计时停不下来
- **自动监视的会话必须经过 CANDIDATE 观察期**（默认 5 秒），别退回到「一看到进程就建会话」
- **轮询间隔分三档**：有人在计时 3 秒、只开自动监视 10 秒、都没有就不轮询。别退回固定 3 秒（一天会多跑一万多次 `tasklist`）
- **查进程真实路径要调 PowerShell，约 1.5 秒**，只能低频或按需，不能塞进每一轮巡检

## 已知限制

- **只支持 Windows**
- **只测「进程在不在跑」，不测你有没有在操作**。游戏开着去吃饭，时间照算——这是刻意的取舍，因为有些人挂着看视频、挂机也算在玩
- 部分游戏藏得很深，启动器交接抓不到。这种情况需要给该软件补一个「关联进程名」
- Windows 的进程启动/退出事件通知需要管理员权限才能订阅，所以没有采用，靠每 3～10 秒看一次进程表。代价是游戏启动后最多晚 10 秒被发现（开始时间会往前推，时长本身不欠）
- 未做代码签名，首次运行可能被杀软拦一下

## 隐私

这个程序不会做的事：

- 不联网、不上传、不注册账号
- 不注入游戏进程、不读游戏内存、不修改任何游戏文件
- 只在后台偶尔看一眼「这个程序还在不在运行」
